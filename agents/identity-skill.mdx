## Why It Matters

Every AI agent today has no real identity — just code running somewhere. You can't prove who owns it or hold anyone accountable. The Verified Agent Identity skill gives each agent a cryptographic DID and links it permanently to a verified human owner on-chain. One human, one attested agent identity.

---

## Install the Skill

Ask your agent directly:

```plaintext
Install the skill `npx clawhub@latest install verified-agent-identity`
```

Or install manually — [clawhub](https://clawhub.ai) is the skill manager for OpenClaw-compatible agents; [skills.sh](https://skills.sh) is a universal skill registry for AI agents:

```bash
# via clawhub
npx clawhub@latest install verified-agent-identity

# via skills.sh
npx skills add BillionsNetwork/verified-agent-identity
```

Once installed, tell your agent to link its identity to you:

```plaintext
Link your agent identity to me.
```

The agent will generate a verification link. Open it in the [Billions Wallet](https://wallet.billions.network) to complete the on-chain pairing.

## How It Works

<Steps>
  <Step title="Install the skill">
    Tell your agent to install the Verified Agent Identity skill. The agent generates its own DID locally using the [iden3 protocol](https://docs.iden3.io) — an open-source ZK identity framework that derives cryptographic identifiers from key pairs. Nothing goes on-chain at this point.
  </Step>
  <Step title="Agent shares a verification link">
    The agent generates a verification link scoped to this specific human-agent pairing and shares it with the human owner.
  </Step>
  <Step title="Human verifies ownership in the Billions Wallet">
    The human opens the link in the Billions Wallet, generates a zero-knowledge Proof of Uniqueness and an auth proof, and submits them to the Relay Attestation Service.
  </Step>
  <Step title="Permanent attestation created on-chain">
    The Relay makes two on-chain calls on the Billions Network. First, the **Identity Verifier Contract** verifies the ZK proof and stores it against the user's DID — enforcing one human, one identity. Then, the **Attestation Registry Contract** creates a permanent on-chain attestation linking the verified human to the agent's DID.
  </Step>
</Steps>

The proofs are on-chain — permanent, public, and immutable. Not in a config file. Not in a database someone controls.

## Architecture

![Verified Agent Identity skill architecture](/images/skill-architecture.png)

Five components make this work together:

| Component | Role |
|---|---|
| **Verified Agent Identity skill** | Installed on the agent; derives its DID and orchestrates the linking flow |
| **Billions Wallet** | Used by the human to generate ZK proofs and approve the pairing |
| **Zero-Knowledge Proof of Uniqueness** | Proves the human is real and unique without revealing personal data |
| **Identity Verifier Contract** | Verifies the ZK proof on-chain; enforces one verified human = one identity |
| **Attestation Registry Contract** | Creates the permanent on-chain link between the verified human and the agent's DID |

The Identity Verifier Contract is Sybil resistant by design — one verified human can only attest to one agent identity.

## Technical Details

<AccordionGroup>
  <Accordion title="How the skill runs">
    The skill requires **Node.js >= v20** and npm. When installed, it adds a `scripts/` directory to the agent's workspace and runs `npm install` to set up dependencies.

    All cryptographic material is stored in `$HOME/.openclaw/billions/` (OpenClaw's data directory) — outside the agent's workspace — so identity data persists across sessions and agent restarts. The agent reads this directory on startup to load its default DID and private keys.

    When the agent receives a natural-language trigger (e.g. "link your identity to me"), the skill's instruction set maps it to the appropriate script, executes it as a subprocess, and returns the result to the conversation.
  </Accordion>
  <Accordion title="Pairing and attestation flow (tech spec)">
    When the human clicks the verification link, the Billions Wallet initiates the following sequence:

    1. **Auth proof** — a JWS token is generated, signed with the agent's private key, proving DID ownership.
    2. **Proof of Uniqueness** — a ZK proof is generated in the wallet, proving the human is a real, unique individual without revealing personal data.
    3. Both proofs are submitted to the **Relay Attestation Service**.
    4. The Relay calls the **Identity Verifier Contract** on the Billions Network — the ZK proof is verified on-chain and stored against the user's DID. This enforces uniqueness: the same human cannot attest to multiple agent identities.
    5. The Relay calls the **Attestation Registry Contract** (ERC-8004, a standard for on-chain attestation registries) — a permanent on-chain attestation is written linking the verified human's DID to the agent's DID.

    The attestation is public, immutable, and queryable by any third party to confirm agent ownership.
  </Accordion>
</AccordionGroup>
