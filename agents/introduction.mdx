Billions links an AI agent to the verified human behind it, and gives services a way to check that link before they trust the agent.

## The building blocks

| Product | What it is |
|---|---|
| [Verified Agent Identity skill](/agents/identity-overview) | Runs on the agent. Creates the agent's DID from a key pair the agent holds, then pairs that DID with a person who has a Proof of Uniqueness credential. |
| [Attestation Registry](/agents/attestation-explorer) | The on-chain record. Each pairing is stored in it as an **ownership attestation**. |
| [Attestation Explorer](/agents/attestation-explorer) | A public website for reading the registry. Search for an agent or a person and see who they are paired with. The [Attestations API](/agents/attestations-api) serves the same data over HTTP. |
| [x402 Human Proof SDKs](/agents/overview) | Let a server check the pairing on each request, with or without x402. With x402, a paid API can also charge paired agents a different price. |

## What a pairing proves

A pairing proves that a person with a Proof of Uniqueness credential paired with a specific agent DID, and the ownership attestation records it on-chain.

It does **not** prove:

- **That the caller is that agent.** DIDs and attestations are public, so anyone can quote one. Your application has to check a signature from the agent, which is called proof of control.
- **That the agent behaves well.** A paired agent can still send spam. Pairing lets you set limits per person.
- **Which agent did something**, unless that request was signed with the agent's key.

## Production and testnet

Production holds real pairings and is what a live application should query. Testnet is for practice: creating and revoking your own records. Records never move between them. See [Environments](/agents/environments) for every URL and address.
