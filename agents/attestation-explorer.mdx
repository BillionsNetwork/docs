Every successful [human-agent pairing](/agents/identity-architecture) writes a permanent record to the on-chain **Attestation Registry**. The **Attestation Explorer** is the public interface for querying it — no special access required.

<Card title="Attestation Explorer" icon="arrow-up-right-from-square" href="https://attestations-explorer.billions.network/">
  attestations-explorer.billions.network
</Card>

## Using the Explorer

The Explorer supports lookups in both directions:

<CardGroup cols={2}>
  <Card title="Look up an Agent DID" icon="robot">
    Paste an agent's DID to see the Human DID it's attested to, if any. No result means the agent hasn't completed the human-linking flow yet.
  </Card>
  <Card title="Look up a Human DID" icon="user">
    Paste a human's DID to see every agent DID attested to them, and the total count of agents they've verified ownership of.
  </Card>
</CardGroup>

<Info>
  An attestation is created only after the human completes the linking flow described in [How It Works](/agents/identity-architecture), and neither the agent nor its owner can self-report or fake one. Because the **Identity Verifier Contract** enforces one verified human per on-chain identity, the human side of every attestation is guaranteed Sybil-resistant.
</Info>

<Note>
  A lookup here only confirms an attestation exists — it doesn't confirm you're talking to the DID's actual owner. See [Verifying Human-Agent Pairing](/agents/verify-human-agent-pairing) for the full check.
</Note>

## Schemas

Every attestation is written against a schema: a typed definition of what fields it records, registered once on-chain in the **Schema Registry** and then reused by every attestation of that kind. A schema also carries an optional resolver contract (custom validation logic run when an attestation against it is created) and a revocable flag (whether attestations of that schema can later be revoked).

The registry currently holds four schemas:

| Name | Fields |
|---|---|
| `AgentOwnership` | `bytes data` — the schema behind every human-agent pairing on this page |
| `AgentDIDAuth` | `uint256 agentId`, `string agentDomain`, +3 more |
| `Review` | `uint8 stars`, `string comment` |
| `ERC8004Registration` | `uint256 chainId`, `address agentRegistryAddress`, +1 more |

`AgentOwnership` is the only one in active use for human-agent verification; the others exist in the registry but aren't yet backing any real attestations. New schemas can be registered by anyone, so this list will grow.

### Creating a Schema

<Steps>
  <Step title="Open Create Schema">
    From the Schemas view in the Explorer, click **Create schema**.
  </Step>
  <Step title="Name it and define its fields">
    Give it a schema name, then add one or more fields, each with a name and a type (string, uint256, address, bytes, and so on). Check **Array** on a field to make it a list of that type instead of a single value.
  </Step>
  <Step title="Set a resolver (optional)">
    Enter a resolver contract address if attestations of this schema need custom validation logic when they're created. Leave it blank for a plain data schema with no extra checks.
  </Step>
  <Step title="Choose revocability">
    Check the box if attestations of this schema should ever be revocable.
  </Step>
  <Step title="Create it">
    Click **Create schema**. This writes a transaction to the Schema Registry contract and returns a schema ID, the same kind of ID used as `schemaId` when querying or creating attestations against it.
  </Step>
</Steps>
