## Overview

The Billions Web Wallet is a secure, browser-based identity wallet designed for streamlined credential issuance and verification. It enables users to manage their digital identity credentials through seamless sign-in with Google, Apple ID, or a crypto wallet.

The wallet supports multi-device access, embedded credential issuance, and both on-chain and off-chain verification — providing a comprehensive solution for managing and verifying digital credentials across platforms.

## Quick Start

The Web Wallet is accessible at [wallet.billions.network](https://wallet.billions.network). To get started, sign in with Google, Apple ID, or a crypto wallet, and create your identity.

<Tip>
  Experience the Web Wallet through the [demo application](https://demo.billions.network), which showcases **Human**, **Verified Human**, and **Uniqueness** verification flows.
</Tip>

## Credential Storage

<Info>
  **End-to-End Encrypted Cloud Storage**

  Credentials are encrypted and stored in cloud storage, providing secure multi-device access and a reliable backup solution. Upon sign-in — via Google, Apple ID, or a crypto wallet — an identity is derived and storage keys are generated.

  - **Signature scheme:** ed25519
  - **Encryption:** AES256-GCM
  - **Access:** Only the user holding the storage keys can decrypt and access their credentials

  No credentials are stored in plaintext at any point. The cloud storage acts solely as a secure, encrypted repository — the decryption keys never leave the user's control.
</Info>

<Note>
  To sync your identity and credentials between the Billions Web Wallet and the Billions Wallet App, you must sign in with the same account on both platforms.
</Note>

## Verification Journey

The following walkthrough describes the end-to-end user experience for verification.

<Steps>
  <Step title="Initiate">
    The user clicks the designated action in the application, which triggers a redirect to the Web Wallet.
  </Step>
  <Step title="Sign In">
    The user selects **Sign In** and authenticates using Google, Apple ID, or a crypto wallet.
  </Step>
  <Step title="Load Identity">
    An identity wallet is derived from the user's account and the associated encrypted credentials are retrieved from cloud storage.
  </Step>
  <Step title="Claim Credential">
    If the required credential has not yet been issued, the user selects **Claim Credential** and completes the issuance flow (e.g. a uniqueness check for Proof of Uniqueness).
  </Step>
  <Step title="Generate Proof">
    Once the credential is available, the user selects **Verify**. A zero-knowledge proof is generated and submitted to the verifier — either off-chain or to a smart contract for on-chain verification.
  </Step>
  <Step title="Complete Verification">
    The user is redirected back to the application, where the verification result is confirmed and the application flow continues.
  </Step>
</Steps>
